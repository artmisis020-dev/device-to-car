# MediaMTX SRT-latency патч

## Проблема

MediaMTX (усі версії, перевірено v1.11.3 і поточний `main`) не має жодного
конфіг-ключа для затримки прийому SRT (`mediamtx.yml` дає лише `srt`/
`srtAddress`/`srtReadPassphrase`/`srtPublishPassphrase`). Всередині
(`internal/servers/srt/server.go`) сервер створює конфіг через
`srt.DefaultConfig()` (бібліотека `github.com/datarhei/gosrt`) і ніде не
перевизначає `ReceiverLatency`/`PeerLatency` — а дефолт цієї бібліотеки
**120 мс**. Оскільки в SRT ефективна затримка = `MAX(запит відправника,
затримка отримувача)`, ці 120 мс з боку MediaMTX домінували незалежно від
того, що просив RPi (`latency=...` в URI `srtsink`), і були основним внеском
у наскрізну (glass-to-glass) затримку відеостріму (~250мс → ~190мс лишень
від зниження RPi-сторони, повне прибирання цієї "підлоги" дало ще ~100мс).

## Рішення

Патч (`srt-latency.patch`) додає 2 рядки одразу після `srt.DefaultConfig()`,
що встановлюють `ReceiverLatency`/`PeerLatency = 10ms`. Значення підібране й
перевірено наживо на реальному лінку РПі↔адмін-сервер (WireGuard,
`msRTT` ≈ 1.9-2.3мс): втрати пакетів (`packetsReceivedDrop` в
`/v3/srtconns/list`) лишались у межах шуму (~0.1-0.3% за тестові інтервали),
відео без видимих артефактів.

## Файли в цій директорії

- `srt-latency.patch` — сам патч (git diff проти тегу `v1.11.3`).
- `build.sh` — відтворює збірку з нуля (клонує тег, застосовує патч,
  `go generate` + `go build CGO_ENABLED=0 GOOS=linux GOARCH=amd64`,
  видає бінарник `mediamtx-v<VERSION>-srt10ms_linux_amd64`).
- `mediamtx-v1.11.3-srt10ms_linux_amd64` — готовий бінарник (закомічений,
  щоб `deploy.sh` міг просто поставити його на сервер — сервер сам зібрати
  Go-проєкт не може: 1 CPU, 1.9GB RAM без свопу, Go не встановлено).

Версія показує себе як `v1.11.3-dirty` (`mediamtx --version`) — це навмисно,
відрізняє патчений білд від офіційного релізу з тим самим номером версії.

## При апгрейді MEDIAMTX_VERSION

`install_mediamtx.sh` спершу шукає готовий бінарник
`mediamtx-v${MEDIAMTX_VERSION}-srt10ms_linux_amd64` саме в цій директорії й
ставить його замість завантаження офіційного релізу. Якщо піднімаєте
`MEDIAMTX_VERSION` — **обов'язково** перезапустіть `build.sh` з новим
`MEDIAMTX_VERSION=X.Y.Z ./build.sh`, перевірте що патч і далі накладається
без конфліктів (рядок з `srt.DefaultConfig()` рідко змінюється, але треба
дивитись), закомітьте новий бінарник — інакше `install_mediamtx.sh` мовчки
відкотиться на офіційний білд зі стоковими 120мс, і ніхто про це не
дізнається, поки хтось знову не почне міряти затримку.
